# Troubleshooting

Start with `praxis_doctor` for the repository: `approval.mode`, `approval.client`, `build`, `nextSteps`. See [Diagnostics](./diagnostics.md).

| Symptom | Cause | Fix |
| --- | --- | --- |
| A protected apply returns `APPROVAL_CLIENT_UI_REQUIRED`, result says "NOT executed", `executed: false`, preview attached | The client declared no form-mode elicitation (`approval.mode: no-dialog`; `approval.client.reason` says why). Claude Desktop Chat is the verified example. Nothing the agent or you type can substitute | Use a client that shows the approval dialog (Claude Code). Or, if you own the setup and accept the trade-off, set Approval mode to `trusted-client` or `host-permission` ([Security model](./security-model.md)). Read-only tools and previews keep working |
| A protected apply in Claude Desktop Chat shows no result for minutes (the 4-minute hang seen in a real test) | Desktop's own tool-permission prompt holds the call before it reaches Praxis. Desktop's log has `tool_approval_gate ... approvalRequired:true`; Praxis has no `tool_enter` for the call | Find the permission prompt in the Desktop window and answer it. Check `~/.praxis/diagnostics/mcp.jsonl`: `tool_enter` then `tool_finished` means Praxis answered; no `tool_enter` means Desktop never passed it on. "Allow once" is safer than "Always allow" |
| `APPROVAL_TIMED_OUT` | The client declared a dialog but nobody answered within 10 minutes. Nothing executed. Neither a rejection nor an approval | Ask the agent to run the apply again to get a new dialog |
| `APPROVAL_REJECTED` | You rejected, dismissed or cancelled the dialog, or the agent passed `confirmation=NO` | Nothing was changed. Ask for a new preview if you want to proceed |
| `APPROVAL_FINGERPRINT_MISMATCH` | The `previewFingerprint` no longer matches the live plan: the repository, Jira or workflow state changed after the preview | Run the matching `*_preview` tool again, show the new preview, then apply |
| `APPROVAL_SCOPE_MISMATCH` or `APPROVAL_EXPIRED` | The approval was for different content, or older than 10 minutes | Preview and approve again |
| `APPROVAL_REQUIRED` | A mutation was attempted outside an approved Praxis action (for example a direct library call) | Run it through the apply tool |
| `JIRA_CONFIG_UNAVAILABLE: missing jira_base_url, ...` | A Jira tool was called without the needed settings. Local tools are unaffected | Set the missing settings (extension settings, or `PRAXIS_JIRA_*` environment variables for CLI and plugins). Do not paste tokens into chat. Not needed for local workflows |
| A Jira, GitHub or GitLab setting shows as blank or as `${user_config...}` | A blank optional extension setting | Ignore: it is treated as unset and listed in `hostPlaceholdersIgnored` |
| `PRAXIS_RUNTIME_UNAVAILABLE` (reported by a role skill) or no `praxis_*` tools in the client | The Runtime is not connected in this client. Claude Code, Desktop Code, Cowork get it from the `praxis-runtime` plugin; Desktop Chat from `praxis-runtime.mcpb`; Web Chat has none | Install through the marketplace (`claude plugin install praxis@praxis`) or install `praxis-runtime.mcpb` in Desktop Chat. Start a new session. Check `claude plugin list` |
| A role skill is installed but the Runtime is not | The role plugin was installed from a ZIP, or `praxis-runtime` was disabled or removed. Dependencies are declared only in marketplace entries, so a ZIP does not bring the Runtime | Install the role from the marketplace (`claude plugin install praxis-ba@praxis` installs `praxis-runtime` as a dependency), or enable `praxis-runtime` |
| Old behaviour after an update, wrong tool count, older `build.version` | A stale old extension or plugin: a session started before the update keeps its tool list, or an older installation is still loaded | Quit the client completely and open a **new** session or chat. Compare `build.bundleSha256` and `build.tools.count` (52) with the installed file. For Desktop, uninstall the old extension before installing the new `.mcpb` (the version string may be unchanged). `npm run report:tool-origins` in praxis-runtime lists the origins |
| Two sets of identical `praxis_*` tools, or protected calls answered inconsistently | Duplicate Runtime: the `praxis-runtime` plugin and the `.mcpb` extension are both active in the same client, or an old copy is still enabled | Keep one. Desktop Chat uses the `.mcpb`; Code and Cowork use the plugin. Disable or uninstall the other. A marketplace install yields exactly one server |
| Quality tools answer from an old service, port 8792 busy | An old Quality service process kept the port and answers for the new Runtime | Quit the client, find the old process (`pgrep -fl "praxis-quality.cjs\|praxis-mcp.cjs"`), stop it if it is the old Praxis service, reopen. `praxis_quality_status` and `praxis_quality_ensure` show the state |
| `dotenvRejected` lists keys | A repository `.env` tried to set `PRAXIS_APPROVAL_*`, `PRAXIS_ALLOW_*`, `PRAXIS_FIXTURE_*` or `PRAXIS_TEST_*`; they were ignored | Remove them from the file; set approval mode only in the extension settings or the real environment |
| Trusted Client set in `.env` does nothing | Approval settings are never read from repository files | Set `PRAXIS_APPROVAL_MODE` in the environment before starting `claude`, or in the extension setting (Desktop) |
| `PRAXIS_MCP_ROLE_INVALID` or `PRAXIS_MCP_START_FAILED` on stderr | The server was started with a wrong `--role` (expected `ba`, `architect`, `developer`, `quality` or `runtime`), or failed to start | Use the shipped plugin or MCPB (`--role runtime`). Check Node.js is 20 or newer |
| `WORK_ITEM_SELECTION_REQUIRED` | A fresh clone has several work items and no current selection | Pass `workItemId`, or run the `select-work-item` workflow command |
| `WORKFLOW_CONFLICT` | A legacy `state.json` and `items/` both exist | See `PRAXIS-STATE-POLICY.md` in praxis-runtime |

Not verified: Trusted Client from a live Claude Code session; behaviour of the Claude UI plugin manager; marketplace install in Claude Desktop Chat.
